# Agent notes

## Commands
- Tests: `uv run python -m pytest tests -q` (`tests/test_api.py` loads the real local pipeline, ~4 min; `tests/test_model_runtime.py` is fast and offline)
- Adding dependencies: `uv --system-certs add <pkg>` (the corporate network needs system TLS certificates)
- DeepEval dry runs (no model calls): `uv run python eval/deepEval/full_pipeline_eval.py --dry-run`, `uv run python eval/deepEval/generator_eval.py --dry-run`

## Configuration
- `.env` controls everything; `src/config/settings.py` is the schema/defaults.
- `MODEL_EXECUTION_MODE=local|huggingface_api` (plus per-stage overrides) selects where embedding, reranking and generation run; backend selection lives only in `src/model_runtime/factory.py`.
- `VECTOR_STORE=numpy|qdrant` selects the retrieval index. Qdrant mode: `docker compose up -d qdrant`, then `uv run python scripts/migrate_npy_to_qdrant.py` (no re-embedding); settings are `QDRANT_URL`, `QDRANT_COLLECTION`, `QDRANT_API_KEY`. Code is in `src/vector_store/` and `src/retriever/qdrant_retriever.py`. Keep the Qdrant server version close to the `qdrant-client` version.
- Qdrant also stores the filing catalog (`filing` payload key, from `data/parsed/*.document.json`); `INCLUDE_DATA=false` builds the Docker image without `data/`. `tests/test_qdrant_store.py` is fast and offline (Qdrant `:memory:` mode).
- API security: `API_ACCESS_KEY` (X-API-Key, required in prod), Supabase JWT (`SUPABASE_URL` / `SUPABASE_JWT_SECRET`), rate limits via `RATE_LIMIT_*` (Redis in Docker, in-memory otherwise). Code in `api/auth.py`, `api/security.py`, `api/rate_limit.py`; the frontend proxy is `web/app/api/[...path]/route.ts`. See `DOCKER.md`.
- Do not print or commit `.env` contents (contains API keys).
- Agent settings use the `AGENT_*` prefix. `AGENT_LLM_PROVIDER` / `AGENT_LLM_MODEL` inherit the generation provider/model when empty; `HISTORY_STORE=none|postgres` controls persistence and Postgres requires the server-only `HISTORY_DB_URL` (`SUPABASE_DB_URL` is accepted as a fallback).
- History is plain Postgres (`src/persistence/history.py`, sync psycopg pool). Locally: `docker compose --profile history up -d postgres` (needs `POSTGRES_PASSWORD`), then `uv run python scripts/apply_migrations.py`. On Supabase add `--supabase` to also apply the RLS policies in `db/supabase/`. Without Supabase auth, `HISTORY_DEV_USER_ID` (dev only) owns saved history. `tests/test_history.py` runs offline; its live Postgres tests run only when `HISTORY_TEST_DB_URL` is set (each uses a temporary schema that it drops). Use `127.0.0.1`, not `localhost`, in local Postgres URLs: on Windows `localhost` tries IPv6 first and stalls until `connect_timeout`.
- Research chat: `POST /chat` (`api/routers/chat.py`) streams SSE events `thread → step/tool… → answer|clarification|error → done` from `AgentService` (`src/agent/service.py`), built in the lifespan on the generator's loaded retriever/reranker (needs `VECTOR_STORE=qdrant`; otherwise `/chat` returns 503 and `/questions` is unaffected). Resume a clarification with `{"thread_id", "resume": {"option_id"|"text"}}`. Checkpoints are namespaced by owner (`owner:thread_id`). `AGENT_CHECKPOINTER=memory` (default) keeps them in process memory, so a restart expires pending clarifications (`clarification_expired`) and drops follow-up context; `AGENT_CHECKPOINTER=postgres` stores them in `HISTORY_DB_URL` via `ThreadedPostgresSaver` (`src/persistence/checkpoints.py`: sync `PostgresSaver` run in worker threads, because async psycopg cannot run on the Windows Proactor loop). Its tables are created at startup (`saver.setup()`); an unreachable database disables `/chat` (no fallback to memory). Runs use `durability="exit"` (one checkpoint write per turn) and finished turns prune the thread to its latest checkpoint. `tests/test_checkpoints.py` covers it; its live tests also use `HISTORY_TEST_DB_URL`. Turns are saved to history and to `logs/metrics/queries-*.jsonl` as `record_type="agent"`. `tests/test_chat.py` is offline (scripted LLMs).
- Agent smoke run against Docker Qdrant + local Ollama: `HF_HUB_OFFLINE=1 uv run python scripts/agent_smoke.py [--max-tool-steps 0|2|6] [--only id,id]` (writes `eval/agent_smoke/*.jsonl`). Ollama needs `OLLAMA_NUM_CTX` ≥ 16384 for research synthesis; with the server default (4096) every multi-filing answer fails.
- Logging: every log line carries correlation ids from context variables (`config/logging.py`: `log_context`, `LogContextFilter`). The middleware binds `request_id` (the `X-Correlation-ID`), `AgentService.stream` binds `thread_id`/`turn_id`; they follow asyncio tasks and `asyncio.to_thread`. Text format shows `[req=<8> turn=<8>]`; `LOG_FORMAT=json` (production, stdout) adds `request_id`, `thread_id`, `turn_id` and any `extra=` fields. Each chat turn always logs `Chat turn started` and one `Chat turn finished: status=… outcome=… tokens=… valid=… trace=<path>` line.
- Debugging a chat turn: `AGENT_TRACE=off|errors|all` (`true`=all). `AgentService` attaches `TurnTrace` (`src/agent/trace.py`, a LangChain callback, also the sink for `observability.tracing.trace_event`). The trace has: the request; every LLM call (node, full prompt, schema/tools, raw output, tokens, timing, errors); every retrieval (`trace_retrieval` in `agent/tools.py` and `generation/generator.py`: query, filters, each hit's chunk/filing/section/score, seconds), including the single-filing generator's prompt and raw response; step events; each node's state update; code decisions (`kind="decision"`: analysis grounding, context selection with kept S# and dropped chunks, `ground_claims` changes, repair/first-draft choice); failures with traceback; the events sent to the client; history and metrics writes. `all` logs one line per event and writes every turn to `logs/agent_traces/<time>_<turn>.json` (`_req-<id>` for rejected turns); `errors` (production) writes only failed, timed-out, cancelled, rejected, invalid, empty or trimmed turns and logs only warnings. Add events from new code with `trace_event(kind, summary, **data)` (no-op outside a traced turn). Structured-output fallbacks are logged by `agent.llm` as warnings.
- The 7B analyze model is unreliable on `scope`/`companies`; `_ground_analysis` in `src/agent/nodes.py` applies code-side corrections. Synthesis uses `SynthesisDraft` (required `answer` + `claims`); coverage is derived by code. Optional fields in a structured-output schema are often left empty by Ollama models.
- Web: research chat is `web/components/ChatWorkspace.tsx` (mode switch in `AppShell.tsx`); `streamChat` in `web/lib/api.ts` parses SSE from `fetch` (EventSource is GET-only). Checks: `npm run lint`, `npm run typecheck`, `npm run build` in `web/`.
- Performance eval (latency P50/P95/P99 per component, cold vs warm, cost, reliability): `uv run python eval/old_results/performance/performance_eval.py direct|api|analyze` (`--dry-run` makes no model calls; `analyze` summarizes `logs/metrics/queries-*.jsonl` from production). Shared code is `src/observability/`; `tests/test_observability.py` is fast and offline.
